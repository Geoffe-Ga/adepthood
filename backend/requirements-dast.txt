# DAST-only tooling, installed by .github/workflows/dast-contract.yml and by
# nothing else. Exact (==) pins, like every other requirements file here, so a
# gate's verdict never depends on the day it ran.
#
# Deliberately NOT in requirements-dev.txt, for three reasons:
#   1. `scripts/backend/deps.sh` compares requirements.txt + requirements-dev.txt
#      against the *installed* environment on every local run of check-all.sh. A
#      pin there is a pin every contributor must install to run lint, for a tool
#      no local gate invokes.
#   2. Schemathesis depends on PyYAML, which this repository deliberately keeps
#      out of all three of the other requirements files -- see the docstring of
#      backend/tests/test_integration_lane_guard.py, which parses a workflow as
#      text precisely because `import yaml` would be a collection error.
#   3. It also pulls hypothesis, jsonschema-rs, werkzeug, requests, rich and
#      pyrate-limiter. That is a large transitive surface to add to every
#      developer's environment for one CI job.
#
# Dependabot's pip ecosystem is configured for /backend and discovers the
# requirements files in that directory, so upgrades here are still proposed.
#
# It installs cleanly into the shared development virtualenv all the same --
# `pip install -r backend/requirements-dast.txt` adds ten packages and changes
# the version of nothing already pinned -- and you need it to run
# backend/tests/scripts/dast/test_contract_fuzz_catches_a_planted_bug.py, which
# runs this exact pin against a deliberately broken application and requires it
# to fail. Without the executable that suite skips, with a reason naming this
# file; in the DAST workflow, which sets DAST_LANE_REQUIRE_SCHEMATHESIS, the
# same absence is a red job instead.
schemathesis==4.25.2
